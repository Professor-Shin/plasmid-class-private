# รายงาน: ESM-2 + Attention Pooling บน RefSeq Plasmid vs Chromosome Dataset

เอกสารนี้รายงานการนำสถาปัตยกรรมที่ออกแบบไว้เองใน `../old resource/`
(`09_train_esm2.py`, `10_esm_attention.py`) มา **เขียนใหม่และเทรน/วัดผลบนชุดข้อมูลปัจจุบัน**
พร้อมเปรียบเทียบกับ baseline สามตัวใน `../baseline` (PlasFlow, Zou et al., PlasClass)
บน fragment ชุดเดียวกันแบบจับคู่ตรง ๆ

> **สรุปผลโดยย่อ**
> ที่ระดับ fragment ESM-2 + attention **ไม่ชนะ** baseline แบบ k-mer — ได้ F1 0.160 / MCC 0.221 /
> AUPRC 0.146 ซึ่งเท่ากับ PlasFlow-balanced และต่ำกว่า Zou-balanced (0.169 / 0.234 / 0.198)
> และต่ำกว่าผลดีที่สุดโดยรวม (Zou-full + จูน threshold: F1 0.348 / MCC 0.332) อยู่ราว 1.5 เท่า
> แต่ **ที่ระดับ replicon กลับได้ AUPRC สูงที่สุดในทุกโมเดล (0.9260)** และมี recall สูงที่สุด
> ในกลุ่มที่เทรนแบบสมดุล บ่งชี้ว่าสัญญาณที่ได้จากโปรตีนต่างจากสัญญาณ k-mer และน่าจะนำไปรวมกันได้

## 1. สถาปัตยกรรมที่นำมาทดสอบ

```
fragment DNA 5,000 bp
   → แปลรหัส 6 เฟรม (3 เฟรม × 2 สาย) ตัดที่ stop codon เก็บเปปไทด์ ≥ 100 aa (เอายาวสุด 10 ชิ้น)
   → ESM-2 (facebook/esm2_t6_8M_UR50D) เฉลี่ยเวกเตอร์ทุกกรดอะมิโน → 320 มิติต่อหนึ่ง ORF
   → attention pooling ที่เรียนรู้ได้ ถ่วงน้ำหนักแต่ละ ORF → context 320 มิติ
   → Linear(320→64) → ReLU → Dropout(0.3) → Linear(64→1) → ความน่าจะเป็นว่าเป็น plasmid
```

จุดเด่นเชิงแนวคิดที่ต่างจาก baseline ทั้งสอง: **ไม่ได้ดูสถิติของลำดับดีเอ็นเอโดยตรง**
แต่แปลงเป็นโปรตีนก่อน แล้วให้ protein language model ที่เรียนรู้มาจากโปรตีน 65 ล้านลำดับ
(UniRef50) เป็นผู้สกัดความหมายเชิงหน้าที่ ก่อนให้ attention เลือกว่า ORF ไหนในชิ้นส่วนนั้น
สำคัญต่อการตัดสิน — สมมติฐานคือ plasmid มียีนลักษณะเฉพาะ (replication, mobilization,
conjugation, toxin-antitoxin, AMR) ที่โมเดลโปรตีนน่าจะจับได้ แม้องค์ประกอบ k-mer จะคล้ายโครโมโซม

## 2. ข้อมูลและการสุ่มตัวอย่างแบบถ่วงน้ำหนัก

### 2.1 ทำไมต้องสุ่มตัวอย่าง

ESM-2 ใช้เวลาราว **0.44 วินาทีต่อ fragment** บนเครื่องที่ใช้ (วัดจริง ดูหัวข้อ 3.5)
ถ้าจะประมวลผลทั้ง 482,161 fragments ต้องใช้เวลาประมาณ **59 ชั่วโมง** ซึ่งไม่สามารถทำได้
จึงต้องสุ่มตัวอย่าง — แต่สุ่มแบบที่ยังสรุปกลับไปยังประชากรจริงได้

### 2.2 วิธีสุ่มและการถ่วงน้ำหนัก

สุ่ม **แยกตามคลาส** (stratified) แล้วให้แต่ละแถวที่สุ่มมาถือน้ำหนักเท่ากับจำนวนสมาชิก
ที่มันเป็นตัวแทน (ตัวประมาณแบบ Horvitz–Thompson): ถ้าคลาสหนึ่งมี N ชิ้นและสุ่มมา n ชิ้น
แต่ละชิ้นมีน้ำหนัก N/n

| split | plasmid ที่สุ่ม | น้ำหนัก | chromosome ที่สุ่ม | น้ำหนัก | รวมที่ประมวลผล |
|---|---|---|---|---|---|
| train | 4,000 จาก 7,915 | 1.9788 | 4,000 จาก 329,597 | 82.3992 | 8,000 |
| validation | 1,000 จาก 1,696 | 1.6960 | 4,000 จาก 70,621 | 17.6553 | 5,000 |
| **test** | **1,696 จาก 1,696 (ทั้งหมด)** | 1.0000 | 8,000 จาก 70,636 | 8.8295 | 9,696 |

การออกแบบนี้ตั้งใจให้ **test set เก็บ plasmid fragment ครบทุกชิ้น** เพราะคลาสบวกคือคลาสที่หายาก
การมี positive ครบ 1,696 ชิ้นทำให้ค่า recall เป็นค่าจริงไม่ใช่ค่าประมาณ และ precision/F1/MCC/AUPRC
ถูกคำนวณโดยถ่วงน้ำหนัก chromosome ด้วย 8.8295 เพื่อให้สะท้อน prevalence 2.345% ตามความเป็นจริง
(เทียบกับการสุ่มแบบสม่ำเสมอ 9,696 ชิ้นซึ่งจะได้ plasmid เพียง ~227 ชิ้น — การออกแบบนี้ให้
ตัวอย่างบวกมากกว่า 7 เท่าที่ต้นทุนการคำนวณเท่ากัน)

`train` สุ่มแบบสมดุล 1:1 ตามแนวทางเดิมของ prototype (250+250) ซึ่งตรงกับ "ระบอบ A"
ของรายงาน baseline ส่วนการรับมือกับ class imbalance ทำที่ **จุดตัดการตัดสินใจ** โดยเลือก
threshold จาก validation ที่ถ่วงน้ำหนักแล้ว — ตรงกับข้อสรุปข้อ 3 ในหัวข้อ 6.2 ของรายงาน baseline

### 2.3 การเปรียบเทียบกับ baseline แบบจับคู่

`../baseline` บันทึกความน่าจะเป็นราย fragment ของทุกโมเดล (PlasFlow 2 ระบอบ, Zou 2 ระบอบ,
PlasClass 1 ระบอบ) ไว้ทั้ง test split
(`results/probs/*.npy` เรียงตามลำดับแถวเดิมของ `test.csv`) จึงสามารถ **ดึงเฉพาะ 9,696 แถว
ที่ ESM-2 ถูกวัดผล** มาคำนวณ metric ใหม่ด้วยน้ำหนักชุดเดียวกันและโปรโตคอลเลือก threshold
แบบเดียวกันได้ การเปรียบเทียบในหัวข้อ 5 จึงเป็นการวัดบน fragment ชุดเดียวกันเป๊ะ
ไม่ใช่การเทียบตัวเลขข้ามชุดข้อมูล

## 4. วิธีการ

### 4.1 การเรียก ORF จาก fragment

ถอดมาจาก `extract_orfs` ของ prototype โดยไม่เปลี่ยนตรรกะ:

1. แปลรหัสทั้ง 6 เฟรม (เฟรม 0/1/2 ของสายปกติ และของ reverse complement)
2. ตัดสตริงโปรตีนที่ `*` (stop codon) ได้เป็นเปปไทด์ระหว่าง stop
3. เก็บเฉพาะเปปไทด์ยาว ≥ 100 กรดอะมิโน
4. เรียงตามความยาวจากมากไปน้อย เอา 10 ชิ้นแรก

> **ข้อควรทราบเชิงชีววิทยา:** นี่คือ "inter-stop peptide" ไม่ใช่ ORF ตามนิยามที่ต้องมี start codon
> และไม่ได้ผ่านเครื่องมือทำนายยีนอย่าง Prodigal ดังนั้นเปปไทด์ที่ได้จำนวนหนึ่งไม่ใช่โปรตีนจริง
> เราคงพฤติกรรมนี้ไว้ตามต้นแบบเพื่อให้วัดสถาปัตยกรรมเดิมได้ตรง แต่เป็นจุดที่ปรับปรุงได้ในอนาคต
> (ดูหัวข้อ 6)

จากข้อมูลจริง: fragment 5,000 bp ให้ ORF เฉลี่ย **9.25 ชิ้นต่อ fragment** ความยาวเฉลี่ย 305 aa
(มัธยฐาน 259, สูงสุด 1,666) และ **ไม่มี fragment ใดเลยที่ไม่มี ORF** ในชุด train

### 4.2 การสกัดเวกเตอร์ด้วย ESM-2

| รายการ | ค่า |
|---|---|
| checkpoint | `facebook/esm2_t6_8M_UR50D` |
| จำนวนพารามิเตอร์ | 7.41 M (6 ชั้น, hidden 320) |
| การ pool ระดับ ORF | เฉลี่ยเวกเตอร์ทุกตำแหน่งโดยใช้ `attention_mask` (ไม่นับ padding) |
| การตัดความยาว | `truncation=True, max_length=1024` ตาม prototype |
| ผลลัพธ์ต่อ fragment | เมทริกซ์ `(จำนวน ORF, 320)` เก็บเป็น float32 |

น้ำหนักของ ESM-2 **ถูกตรึง (frozen)** ไม่มีการ fine-tune — เหมือน prototype เดิม
สิ่งที่เทรนมีเพียง attention pooling กับ classifier ด้านบน (รวมประมาณ 72,000 พารามิเตอร์)

### 4.3 Attention pooling และ classifier

สำหรับ fragment หนึ่งที่มีเวกเตอร์ ORF ชุด `x ∈ R^(n×320)`

```
score_i   = W₂ · tanh(W₁ · x_i + b₁) + b₂          # W₁: 320→160, W₂: 160→1
α         = softmax(score)                          # ถ่วงน้ำหนักข้าม ORF ทั้ง n ชิ้น
context   = Σ_i α_i · x_i                           # 320 มิติ
logit     = W₄ · Dropout(ReLU(W₃ · context)) + b₄   # W₃: 320→64, W₄: 64→1
```

ฝึกด้วย `BCEWithLogitsLoss` (เทียบเท่า sigmoid + binary cross-entropy ของต้นแบบ)

### 4.4 การเทรน

| พารามิเตอร์ | ค่า | ที่มา |
|---|---|---|
| optimizer | AdamW, lr = 1e-3, weight_decay = 1e-4 | `optim.AdamW(...)` ใน prototype |
| loss | `BCEWithLogitsLoss` | เหมือนต้นแบบ |
| batch size | 1 fragment ต่อหนึ่ง optimization step | ต้นแบบใช้ `batch_size=1` เพราะจำนวน ORF ไม่เท่ากัน |
| epochs | 15 | เหมือนต้นแบบ |
| การเลือกโมเดล | ไม่มี (ใช้โมเดลหลัง epoch ที่ 15) | ต้นแบบไม่มี early stopping |
| จำนวน seed | 3 (42 / 142 / 242) | เพิ่มขึ้นจากต้นแบบที่รันครั้งเดียว |
| ensemble | เฉลี่ยความน่าจะเป็นจาก 3 seed | เพิ่มขึ้น เพื่อดูความเสถียร |

เพื่อไม่ให้เสียข้อมูล เราบันทึก checkpoint ที่ **val AUPRC (ถ่วงน้ำหนัก) ดีที่สุด** ไว้ด้วย
และรายงานผลทั้งสองแบบ (`final` ตามต้นแบบ และ `best epoch`) เพื่อดูว่าการเทรน 15 epoch ตายตัว
ทำให้ overfit หรือไม่ — ปัญหาแบบเดียวกับที่พบใน PlasFlow ในรายงาน baseline

### 4.5 รายการความแตกต่างจาก prototype (deviations)

| หัวข้อ | prototype | ของเรา | เหตุผล |
|---|---|---|---|
| หน่วยข้อมูล | replicon ทั้งเส้น | fragment 5,000 bp | เป็นหน่วยของชุดข้อมูลปัจจุบัน |
| การจัด batch ให้ ESM-2 | ทีละ 8 ORF ภายใน fragment เดียว | เรียงตามความยาวแล้ว batch ตามจำนวน token (8,192) ข้าม fragment | **ได้ embedding ตัวเดียวกัน** (ต่างสูงสุด 1.9e-6 ซึ่งเป็น noise ของ float32) แต่เร็วขึ้น 2.4 เท่าเพราะแทบไม่คำนวณ padding — ตรวจสอบด้วย `verify_components.py` |
| การโหลด ESM-2 | `AutoModel.from_pretrained(...)` (สร้าง pooler ที่สุ่มค่าใหม่แต่ไม่เคยถูกใช้) | เพิ่ม `add_pooling_layer=False` | ต้นแบบใช้เฉพาะ `last_hidden_state` ผลจึงไม่เปลี่ยน แต่ตัดพารามิเตอร์สุ่มที่ไม่ได้ใช้ออก |
| `try/except` ครอบการแปลรหัส | มี (กลืน error ทุกชนิด) | เอาออก | ไม่ให้ข้อผิดพลาดถูกซ่อน |
| ตัวชี้วัด | accuracy, precision, recall, F1 | เพิ่ม MCC, AUROC, AUPRC และ **ถ่วงน้ำหนักตาม prevalence จริง** | ที่ plasmid 2.345% accuracy ไร้ความหมาย (ทายโครโมโซมล้วนได้ 97.66%) |
| threshold | 0.5 ตายตัว | รายงานทั้ง 0.5 และค่าที่จูนบน validation | เป็นปัจจัยที่สำคัญที่สุดตามผลของรายงาน baseline |
| จำนวนรอบการทดลอง | 1 | 3 seed + ensemble | เพื่อดูความแปรปรวน |

### 4.6 การตรวจสอบความถูกต้อง

`verify_components.py` รันก่อนเริ่มทุกครั้ง และผ่านทั้งหมด:

- ผลการเรียก ORF ตรงกับฟังก์ชันของ prototype **ทุกชิ้นทุก fragment** (ทดสอบบน 12 fragment, 110 ORF)
- embedding จากการ batch แบบใหม่ต่างจากวิธีเดิมของ prototype สูงสุด **1.91e-06**
- attention pooling ให้ผลเท่ากับการคำนวณ softmax-weighted sum แบบชัดแจ้ง และผลรวมน้ำหนัก = 1

- ไม่มี fragment ใดเลยที่ไม่มี ORF ทั้งสาม split จึงไม่มีการใช้เวกเตอร์ศูนย์แทนที่เลย

## 6. อภิปราย

### 6.1 ทำไม protein language model ถึงไม่ชนะ k-mer

ผลนี้ขัดกับความคาดหมายตั้งต้น (ว่าโมเดลโปรตีนน่าจะจับยีนเฉพาะของ plasmid ได้ดีกว่าสถิติ k-mer)
คำอธิบายที่เป็นไปได้ เรียงตามน้ำหนักหลักฐาน:

1. **fragment 5 kb สั้นเกินไปสำหรับวิธีนี้** — ได้ ORF เฉลี่ยเพียง 9.25 ชิ้นต่อ fragment
   และหลายชิ้นเป็นเปปไทด์ที่ถูกตัดขาดที่ขอบ fragment ไม่ใช่โปรตีนสมบูรณ์
   attention pooling ที่ออกแบบมาเพื่อ "เลือก ORF สำคัญจากหลายสิบ–หลายร้อยชิ้น" จึงแทบไม่มีอะไรให้เลือก
   ต่างจาก prototype เดิมที่ทำงานบน replicon ทั้งเส้น
2. **ESM-2 ขนาด 8M เป็นรุ่นเล็กที่สุดของตระกูล** (6 ชั้น, hidden 320) ถูกเลือกใน prototype
   เพื่อให้รันไหวบนเครื่องธรรมดา รุ่นใหญ่ (35M / 150M / 650M) น่าจะให้ representation ที่ดีกว่ามาก
3. **น้ำหนัก ESM-2 ถูกแช่แข็ง** มีพารามิเตอร์ที่เรียนรู้จริงเพียง ~72,000 ตัว เทียบกับ Zou ที่มี
   ~650,000 ตัวเรียนรู้จากศูนย์บนข้อมูลชุดนี้โดยตรง
4. **"ORF" ที่ใช้ไม่ใช่ยีนจริง** — เป็นเพียงช่วงระหว่าง stop codon ไม่ผ่าน gene prediction
   จึงมีเปปไทด์ที่ไม่ใช่โปรตีนปนอยู่มาก ซึ่งเป็น noise ที่ป้อนเข้า ESM-2 โดยตรง
5. **ข้อมูลเทรนน้อยกว่า** — 8,000 fragments เทียบกับ 15,830 (baseline ระบอบ A)
   และ 337,512 (ระบอบ B) เพราะข้อจำกัดด้านเวลาประมวลผล

### 6.2 จุดที่แนวทางนี้ยังน่าสนใจ

- **ระดับ replicon ได้ AUPRC สูงสุด (0.9260)** แม้ระดับ fragment จะแพ้ แปลว่าสัญญาณที่ ESM-2 จับได้
  **ต่างจาก** สัญญาณที่ k-mer จับได้ และเมื่อรวมหลาย fragment แล้วมันเสริมกันได้ดี
  → มีเหตุผลรองรับที่จะลองทำ **ensemble ระหว่าง ESM-2 กับ Zou** ซึ่งน่าจะดีกว่าตัวใดตัวเดียว
- **recall สูงที่สุดในกลุ่มที่เทรนแบบสมดุล** เหมาะกับงานคัดกรองที่ยอมให้มี false positive ได้
- ต้นทุนการเทรนหัวโมเดลถูกมาก (~4 นาที/seed) ต้นทุนเกือบทั้งหมดอยู่ที่การสกัด embedding
  ซึ่ง **ทำครั้งเดียวแล้ว cache ไว้ใช้ซ้ำได้** การทดลองสถาปัตยกรรมส่วนบนจึงทำซ้ำได้เร็ว

### 6.3 ข้อเสนอสำหรับขั้นต่อไป

เรียงตามอัตราส่วนผลตอบแทนต่อความพยายาม:

1. **ทดลองรวมสองสัญญาณ** — ต่อ (canonical 6-mer 2,080 มิติ) เข้ากับ (context vector 320 มิติ
   จาก attention pooling) แล้วเทรน MLP เดียว ใช้ embedding ที่ cache ไว้แล้ว ไม่ต้องรัน ESM-2 ใหม่
2. **เปลี่ยนไปใช้ ESM-2 รุ่น 35M หรือ 150M** บน fragment ชุดย่อยเดิม เพื่อวัดว่าขนาดโมเดลมีผลแค่ไหน
   (ต้นทุนเพิ่มประมาณ 4–20 เท่าของ 6.3 ชั่วโมง จึงควรลดขนาดตัวอย่างลงก่อน)
3. **ใช้ Prodigal เรียกยีนจริงแทนการตัดที่ stop codon** เพื่อลด noise ที่ป้อนเข้าโมเดลโปรตีน
4. **ถ้าเป้าหมายปลายทางคือระดับ replicon/contig** ให้รายงานผลระดับนั้นเป็นหลัก เพราะแนวทางนี้
   แข็งแรงที่สุดตรงนั้น (AUPRC 0.926)
5. **อย่าใช้ best-epoch checkpoint จาก val AUPRC** — validation ที่ prevalence 2.3%
   ให้สัญญาณ noisy เกินกว่าจะเลือก epoch ได้อย่างน่าเชื่อถือ

### 6.4 ข้อจำกัดของการทดลองนี้

- วัดผลบน **subsample 9,696 fragments** ไม่ใช่ test split เต็ม ค่าที่รายงานเป็นค่าประมาณแบบ
  ถ่วงน้ำหนัก แม้จะ unbiased แต่ก็มี sampling error โดยเฉพาะฝั่ง chromosome ที่สุ่มมา 11.3%
  (ค่า recall ไม่มีปัญหานี้เพราะเก็บ plasmid ครบทุกชิ้น)
- ใช้ ESM-2 รุ่นเล็กที่สุดและไม่ fine-tune จึงยังไม่ใช่ศักยภาพสูงสุดของแนวทางนี้
- เทรนเฉพาะระบอบสมดุล ยังไม่ได้ทดสอบว่าการเทรนบนข้อมูลไม่สมดุลจะช่วยเหมือนที่ช่วย Zou หรือไม่
- ผลระดับ replicon คำนวณจาก fragment ที่สุ่มมาของแต่ละ replicon (สำหรับ chromosome คือราว 11%
  ของ fragment ทั้งหมด) ไม่ใช่ทุก fragment จริง
